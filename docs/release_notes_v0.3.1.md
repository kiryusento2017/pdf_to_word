## 详细说明

上一个正式版是 **v0.3.0**。

### 1. 转换途中还能再加文件

以前一批开转之后，窗口就不收文件了——想加只能等这批转完。

现在**软件里永远只有两个队列**：正在跑的，和攒着的。转换进行中把 PDF
拖进窗口（或者点「再加几份」），它们不会塞进正在跑的那批，而是排进待办，
底下显示「待办 N 份，这批转完自动接上」，每份都能单独移除。等这批全部
转完，待办整批自动接上开始转，**不问**。

不并进当前那批是有原因的：那批的倒计时是开工时估死的、进度条的分母也是
那时定的。中途加文件会让倒计时走到 0 了还在转、进度条因为分母变大而卡住
不动，而它的规矩是「只涨不退」。攒着接上，两个数各自都是诚实的。

摁停止时待办不会丢，并回待转清单，下次一起转。

### 2. 出问题一键生成诊断文件

「关于 → 环境检测」多了个「生成诊断文件」。点一下，软件把能摸到的一切
写成一个 txt，然后弹出资源管理器并选中它，直接拖进微信发出来就行。

里面有：环境细节（CUDA 通道、Office 的 XSL、node、pandoc、用的哪个解释
器）、路径与编码（安装路径和用户名含不含非 ASCII、`%TEMP%` 的长名短名）、
模型实际指向哪、各项磁盘占用、升级状态和备份、最近 50 条转换历史、前端
报错、以及三个日志文件的尾部。

**路径完整保留不脱敏**——路径本身常常就是病根。

某一项读不到不会让整份文件失败，那一行会写「读不到：具体异常」，而那句
话本身往往就是线索。写入位置有三级兜底，文件带 BOM 和 CRLF，记事本直接
打开不乱码、不连成一行。

### 3. 升级识别引擎有后悔药了

装新版之前，软件一直都会把旧版整份备份下来（torch 一份 4 GB 上下），
装到一半断电下次开机会自动爬回来。但**装成功之后那份备份界面上摸不到**
——看不见有哪几份，也没有任何地方能退回去。

现在「关于 → 环境检测」把它们列出来：

```
20260907_145754   torch 2.11.0+cu128   4.14 GB   [退回这一份]
```

中间那列是关键——得先知道退回去会变成什么才好决定。点两次才真退（拷
4 GB 要几分钟，误触代价不小），转换进行中按钮是灰的。退完给一个
「立即重启」按钮，重启之后就是旧版本了。

重启之后那份备份会自己消失——人已经在这个版本上了，再「退回」它没有
意义；真要再升级，装之前又会重新备一份。

**下好的升级包不会跟着丢**：退回之后它还躺在硬盘上，界面上直接还能装
回去，不用重新下 2.8 GB。

### 4. 备份只增不减，退回还删不干净

两个独立的毛病，第二个更麻烦。

**第一个**：装成功之后没有任何人去删旧的那份。删的功能写好了，但它被
放在环境检测页里等用户自己勾，升级流程从头到尾一次都不调。实测在开发机
上堆到过 **12.4 GB**——三份内容几乎一样的备份。

现在同一个版本只留一份，不同版本最多留两个。

**第二个**：一个包在硬盘上是两样东西——本体目录名不带版本号（永远叫
`torch`），元数据目录名带版本号（`torch-2.14.0+cu126`）。退回时照着备份
里的名字删，本体对得上删干净了，元数据因为名字对不上**一个字都没被碰
过**，于是新旧两份并排躺着。每退一次多留一份。

后果不是多占几十 KB：软件问「现在装的是哪个版本」是去数元数据的，有两份
时返回哪个不确定。实测复现过——装的明明是 1.17，问出来是 1.16。而「检查
更新」就靠这个数去跟服务器比，读错就可能明明能升却说「已是最新」。

现在退回时会按包名把这个包的一切痕迹清干净再拷回来。

### 5. 点开「上一批的报告」出不来

待办队列接上之后，转换屏会多一个「上一批的报告」按钮。点进去之后**没有
返回**，只能关软件。

原因是那一屏的内容区被设成占满整个高度，把返回按钮挤到了屏幕外面——
按钮一直都在，只是看不见。现在把它挪到报告前面。

### 6. 转换进行中「关于」不再禁用

以前转换一开始，底部一整排按钮全灰掉，包括只是看看信息的「关于」。

「关于」里绝大多数东西是只读的，转换中看一眼版本号、许可证、环境状态
不该被拦。真正危险的是里面的「检查更新」——更新包覆盖的正是转换要用的
代码，装完还要重启，一重启这批就全废了。

所以保护点下移到「检查更新」自己身上：关于随便进，检查更新在转换中是
灰的，转完自己亮回来。「退回这一份」也一样。
